## 1. 結論

- **修正前の実装では、論文の結果は再現できていなかった。** 論文の仮定を完全に満たす理想データでも、カメラ姿勢 `R0` がまったく推定されず（バンドル調整が収束しない）、周波数推定も、トラック数の上限処理が原因で調査時の合成データでは失敗した（誤差 58〜63%）。オンライン・逐次処理、ループ検出、経過時間による忘却も実装されていなかった。
- **修正後は、論文の全手順（4.1〜4.2.7節、図3）を実装した。** 論文の仮定を満たす合成データでは、周波数（誤差 0.0003% 以下）・`R0`（誤差 0.5° 以下）・3D 構造をいずれも正しく推定できた（6章）。表3のアブレーションのうち、FFT 推定と f の制約なしの劣化は同じ傾向を確認できたが、ランドマーク統合なしの劣化は短い合成実験では確認できなかった。
- **TOPSPIN では未評価である。** 作業環境から Zenodo（TOPSPIN の配布元）へのアクセスがネットワークポリシーで遮断されていたため、実データでの数値（表2・表3）は得られていない。評価コードと手順は用意済み（7章）。

## 2. 修正前の実装の調査結果

### 2.1 調査方法

TOPSPIN が取得できないため、論文の仮定（静止カメラ＋一定角速度スピン）を厳密に満たす合成データを作り、モジュール単位とパイプライン全体で正解と比較した。

1. バックエンド単体: 正解の3D点を軌道モデルで投影した理想トラックを入力した。
2. 周波数推定単体: 理想トラックの観測を入力した。
3. フルパイプライン: 合成イベント（コントラスト閾値モデル）を入力した。

## 3. 論文の記述と修正内容の対照

各項目で、論文に書かれている事実、修正前、修正後の順に記す。

### 3.1 運動モデル（3.1.2節、式(2)〜(5)）

- **論文**: 軌道中心を原点、軌道軸を z 軸、`û = î` とし、`t^w(t; f) = r cos(2πft) î + r sin(2πft) ĵ`。カメラは軌道中心を向く（`r^z = c^w − t^w`、`r̂^x = r̂^z × k̂`、`r̂^y = r̂^z × r̂^x`）。`R0` は軌道面に対するカメラの向きで、時間に依存しない。`r` は観測不能なので任意に固定する（表1: 10）。
- **修正前**: 同じモデルを正しく実装していた。
- **修正後**: モデルはそのまま、`R0` の更新を SO(3) の左摂動で扱う解析的ヤコビアンを追加した。論文の `T_w^t = T_b^t T_w^b` は表記上「カメラ→世界」と「世界→カメラ」が混在しているため、世界→カメラ回転を `R0 · B(t)` とした（`B(t)` の行が `r̂^x, r̂^y, r̂^z`）。これは論文の `R0` を `R0^T` に置き換えた再パラメータ化で、表現できるモデルは同一である。
- **コード**: `espinslam/geometry.py`

### 3.2 フロントエンド（4.1節、図3）

- **論文**: カメラドライバが約 1,000 イベントのチャンク `C` を押し出す。eFAST [35] でコーナーイベント `F ⊆ C` を抽出し、式(6)の同極性密度 `D(e_i) = (1/λ) Σ 1(p_i = p_q)` が平均 `μ_D` 未満のコーナーを除去して `G ⊆ F` を得る。HDBSCAN [32] で `G` を時空間クラスタリングしてトラックレット `M_c` を作り、グローバルなトラックプール `H` に蓄積・統合する。各トラック `H_u` はイベントの集合で、複数チャンクにまたがりうる。
- **修正前**: 2.2節の #6〜#8 のとおり。
- **修正後**:
  - eFAST: 参照実装（rpg_corner_events の `FastDetector::isFeature`）と同じ判定を numba で実装した。極性ごとに SAE（最新タイムスタンプの面）を持ち、半径 3 の円（16 画素）に長さ 3〜6、半径 4 の円（20 画素）に長さ 4〜8 の「最新値の連続弧」があるかで判定する（`espinslam/efast.py`）。
  - 密度フィルタ: 式(6)どおり、同極性の近傍数 / λ が全コーナーの平均以上のものを残す。
  - HDBSCAN: (x, y, t) でクラスタリングし、トラックレットはイベントそのものを保持する。
  - トラックプール: 各トラックは最大 `σ_retain = 1000` イベントの循環バッファ（4.2.7節）。LK と生イベントの代替処理は削除した。
- **コード**: `espinslam/frontend.py`

### 3.3 周波数推定とループ検出（4.2.1節、式(7)〜(9)）

- **論文**: `A` は `H` の全トラックの全イベント。ミッドライフ `τ̂ = 0.5(min t + max t)` で `A_ℓ`（`t ≤ τ̂`）と `A_r`（`t > τ̂`）に分け、`t*_rev = argmin Σ_{m∈A_ℓ} min_{n∈A_r} ‖[x_m, y_m, t_m + t_rev] − [x_n, y_n, t_n]‖_2` を「1D 版の ICP」で解き、`f* = 1/t*_rev` とする。この処理は `H` が更新されるたびに実行し、直近 ℵ 回の推定値の標本標準偏差が σ 未満になったらループ検出とする（表1: ℵ = 20、σ = 10⁻³）。
- **修正前**: 2.2節の #2〜#4 のとおり。
- **修正後**:
  - 式(9)の目的関数（L2 ノルムの和）を、最近傍対応の更新と、対応を固定したシフト量の IRLS 更新（重み 1/d）を交互に行う 1D ICP で解く。
  - ループ検出は ℵ・σ の条件どおり（標本標準偏差、ddof = 1）。検出前は有効な推定値を出力しない（`frequency_at` が NaN を返す）。
  - 検出前は有界な粗探索で初期化し、検出後は現在の推定値から ICP を開始する（4章の解釈 1〜3）。
  - トラック数の上限は撤廃し、4.2.7節の経過時間ベースの忘却に置き換えた。
- **コード**: `espinslam/frequency.py`

### 3.4 構造とカメラ姿勢の最適化（4.2.2節、式(10)(11)）

- **論文**: トラックの各イベントに、`f = f*` で固定した運動モデル(3)から仮想カメラ姿勢を与え、`Σ_u Σ_v ρ(‖π(K R^{t_v}_w x_u + K t^{t_v}_w) − [x_v, y_v]‖_2)` を `R0` と `{x_u}` について最小化する（変数は `3 + 3N_H` 個、GTSAM で解く）。`ρ` は M 推定量（表1: インライア閾値 2）。最適化は `ε/f` 秒ごと（表1: ε = 0.1）。
- **修正前**: 2.2節の #1・#5・#6 のとおり。
- **修正後**:
  - Levenberg–Marquardt 法に Huber の IRLS 重み（GTSAM のロバストノイズモデルと同じ方式）を組み合わせた。ランドマークブロックは Schur 補元で消去し、`R0`（ablation では f も）の 3×3（4×4）系だけを解く。解析的ヤコビアンは数値微分と 1e-8〜1e-10 の精度で一致することをテストで確認している。
  - 保持している全イベントを観測として使い、`ε/f` 秒（イベント時間）ごとに再最適化する。
- **コード**: `espinslam/geometry.py`（`bundle_adjust`）、`espinslam/backend.py`

### 3.5 初期化（4.2.3節）と三角測量（4.2.4節）

- **論文**: 式(11)の最初の実行では、世界点をすべて原点、`R0 = I`、`f = f*` とする。以降は、新規・更新トラックの世界点を、`f*` と最新の `R0` で伝播した仮想カメラからの多視点三角測量 [22] で初期化する。
- **修正前**: `R0 = I` での DLT 三角測量のみ（初回の原点初期化はなし）。
- **修正後**: 論文どおり。初回は原点・`R0 = I` から LM で最適化し、カメラ仰角 40° でも真値に収束する（6.2節）。以降は、新規・更新トラックだけを DLT で三角測量する。
- **コード**: `espinslam/backend.py`

### 3.6 外れ値除去（4.2.5節）

- **論文**: `N_match` 未満のイベントしかないトラックは情報不足として捨てる。ランドマークの平均再投影誤差が γ を超えるトラックを除去する。原点から半径 `r` より外の点も外れ値として捨てる（表1: `N_match = 3`、γ = 10）。
- **修正前**: しきい値は同じだが、除去したトラックはプールに残っていた。
- **修正後**: 3 条件を最適化の後に適用し、除去したトラックはプール `H` からも削除する。
- **コード**: `espinslam/backend.py`

### 3.7 ランドマーク統合（4.2.6節）

- **論文**: 世界点 `x_u1` と `x_u2` の距離が `δ_fuse` 未満なら、対応するトラックを `H_u2 = H_u1 ∪ H_u2` と結合し、次の最適化で 2 点を融合する（表1: `δ_fuse = 0.01`）。
- **修正前**: 最適化後に座標を平均するだけで、トラックは結合していなかった。
- **修正後**: トラックのイベントを結合し（時刻順に並べ、循環バッファを適用）、結合後の点を初期値として最適化する。
- **コード**: `espinslam/backend.py`、`TrackPool.merge`（`espinslam/frontend.py`）

### 3.8 無期限動作（4.2.7節、式(12)）

- **論文**: トラックの年齢 `age(H_u) = max_{A} t − max_{H_u} t` が `σ_forget · t_rev` を超えたら捨てる（表1: `σ_forget = 3`）。各トラックは長さ `σ_retain` の循環バッファ（表1: 10³）。
- **修正前**: トラック数の上限（500）だけで、経過時間による忘却はなかった。
- **修正後**: 論文どおり。ループ検出後、`H` を使う直前（周波数推定と最適化の前）に適用する。
- **コード**: `espinslam/pipeline.py`、`TrackPool.forget`

### 3.9 パイプラインの処理順（図3）

- **論文（図3）**: フロントエンド（eFAST → 密度フィルタ → HDBSCAN）→ トラックレットの統合 → グローバルプール →（更新をトリガとして）ループ検出 →（検出後）初期化 → ランドマーク三角測量 → ランドマーク統合 → 構造・カメラ姿勢の最適化 → 外れ値除去 → 再構成。
- **修正前**: 系列の最後に 1 回だけのバッチ処理。
- **修正後**: チャンク単位のストリーミング処理にした。バックエンドは「三角測量 → ランドマーク統合 → 最適化 → 外れ値除去」の順（`273cf03` で図3の順序に合わせた）。統合は、全点が原点にある初回だけスキップする。
- **コード**: `espinslam/pipeline.py`、`espinslam/backend.py`

## 4. 論文に明記されていない点と採用した解釈

いずれも設定ファイルで変更できる。

1. **式(9)の単位と評価範囲。** 画素と秒をそのまま混ぜると、距離がどちらか一方に支配されて意味をなさない。そのため換算係数 `λ`（`frequency.time_scale_px_per_second`）を導入した。また、シフト後の時刻が `A_r` の範囲に入る `A_ℓ` のイベントだけで評価する。範囲外のイベントは原理的に整列できず、境界のイベントに引き寄せられて `t_rev` を偏らせるためである。実際、範囲外を含めると、プールが 2 回転を超えたあたりから f が 0.5 Hz→0.4965 Hz（誤差 0.7%）と漂流し、限定すると誤差 0.000% になった。
2. **1D ICP の初期値。** ICP は局所解法なので、ループ検出前は有界な粗探索（周期の等比グリッド）で初期化する。コストが最良値から `harmonic_tolerance`（15%）以内の局所最小はすべて ICP で精密化し、その中で最短の周期（基本周期）を選ぶ。ループ検出後は、現在の推定値から ICP を開始してオンラインで追跡する。
3. **推定の実行頻度。** 論文は「`H` が更新されるたび」に実行するとしているが、チャンクごと（約 3 ms ごと）に実行すると Python では遅すぎる。そこで、`H` が変化し、かつ前回から 0.1 秒（イベント時間）以上経過したときに実行する。この場合 ℵ = 20 回分は 2 秒に相当する。`update_interval_seconds: 0` で毎チャンク実行にもできる。
4. **三角測量の視差。** 論文の `N_match = 3` だけでは、1 チャンク分しかないトラック断片（5 イベント以上あるので条件を満たす）が残る。こうした断片は奥行きが決まらない点になる。修正途中の合成実験では、回転角 2° 未満しか追えていないトラックがランドマークの約 76% を占め、それらの点の 90 パーセンタイル誤差は 1.8（物体半径 1.5）に達した。COLMAP の最小三角測量角の既定値にならい、軌道上で 1.5° 未満の弧しかカバーしないトラックは、伸びるまで最適化に入れない（`backend.min_triangulation_angle_deg`）。GTSAM の三角測量も視差のない入力は退けるため、論文の三角測量 [22] にもこの種の判定があったと推測される。
5. **トラックレットのクラスタリングと対応付け。** 論文は HDBSCAN を「時空間で」とだけ述べている。既定では極性ごとにクラスタリングする（式(6)の密度も極性別）。極性を混ぜると（`cluster_by_polarity: false`）、小さな特徴の ON/OFF のコーナーが 1 つのクラスタに合わさる。同じコードで比べると、低解像度の合成シーン（200×150、3 シード）では構造誤差の中央値が 0.095〜0.173 から 0.196〜0.243 に、`R0` 誤差が 0.41〜1.03° から 1.46〜2.48° に悪化した。346×260 のシーンでは差は小さかった（中央値 0.068 vs 0.068、90 パーセンタイル 0.19 vs 0.28）。対応付けは、トラックの最新 5 イベントの中央位置から 5 px 以内・50 ms 以内の最も近いトラックに結合する方式で、同じチャンクの複数トラックレットが同じトラックに合流してもよい。
6. **論文が値を示していないハイパーパラメータ。** 密度フィルタの λ（3 px）、HDBSCAN のパラメータ（最小クラスタサイズ 5、`min_samples` 3、時間スケール 1000 px/s）、対応付けの半径・間隔、式(9)の λ（TOPSPIN 100 px/s、デブリ 200 px/s）、周期の探索範囲（TOPSPIN 2〜60 秒）。TOPSPIN では未調整。
7. **ρ の種類。** 表1は「インライア閾値 2」とだけ書いているので、Huber（閾値 2 px）とした。
8. **`N_match` 未満のトラックの扱い。** 論文は「捨てる」と書いているが、伸びる可能性があるため最適化から外すだけにしてプールには残す。HDBSCAN の最小クラスタサイズ（5）が `N_match`（3）より大きいので、実際には結果に影響しない。
9. **FFT アブレーションの初期化。** FFT の周波数分解能は 1/観測時間なので、σ = 10⁻³ Hz の判定は原理的に通らない。そこで「観測時間が FFT 推定周期の 2 倍を超えたら初期化」とし、ループ閉じ込み法とほぼ同じタイミングで初期化されるようにした。eSfO の FFT 法の詳細は本論文に書かれていないので、トラックイベント数の時系列のスペクトルピークで近似した。
10. **ICP 指標のスケール。** 単眼なのでスケールは観測できない（`r = 10` は任意）。マニフェストにカメラ〜回転軸の実距離 `orbit_radius_mm` があれば、スケールを `orbit_radius_mm / r` に固定する。なければ点群の RMS 半径の比で固定する（ICP 内でスケールを再推定すると、点群が面の一部に潰れて誤差が見かけ上 0 になる）。

| 項目 | 論文 | 本実装 | 理由・影響 |

## 8. デブリ評価への影響

- 論文にない代替処理（LK、生イベント）を削除したので、ループを検出できなかった系列は推定なし（abstention）として扱われる。修正前より有効推定率が下がる可能性があるが、これは論文の手法そのものの挙動である。
- デブリ設定は観測時間を 5 秒に切っているため、ループ検出（約 2 回転＋ℵ 回分の安定化）に間に合うのは、周期がおよそ 2.5 秒以下（約 0.4 Hz 以上）の系列に限られる。
- デブリデータはカメラも動くため論文の前提外であり、評価は再現性ではなく頑健性の比較である。
- 小さな合成デブリ風データ（0.8 Hz、5 秒）で `scripts/evaluate.py` が最後まで動くことを確認した（ω 誤差 1e-8 rad/s）。

## 9. 既知の制約と今後の課題

1. **TOPSPIN での実評価（最優先）。** 7.2節の手順で実行し、7.4節に結果を記入する。データ形式・較正値が想定と違えば、`espinslam/data.py` の読み込みとマニフェストを調整する。
2. **TOPSPIN でのハイパーパラメータ確認。** 4章の 6 に挙げた、論文に値がないパラメータ（特に式(9)の λ と周期の探索範囲）は、TOPSPIN では未確認である。テスト結果を見てから調整することは避ける。
3. **スループット。** HDBSCAN を C 実装や逐次クラスタリングに置き換えれば改善できる。精度には影響しない。
4. **比較手法。** 表2の COLMAP＋ETC Tracks、eSfO、EVO は実装していない。
5. **縮退ケース（4.3節）。** 光軸が回転軸と平行な場合の扱いは、論文同様に対象外。
